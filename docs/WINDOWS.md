## Join an existing server

Install the packaged desktop client, open COLACK, and enter your server connection. The desktop client joins an existing server; hosting is a separate setup step. Retain your account recovery kit privately.

## Host on this computer

1. Use the complete packaged hosting runtime. Open its hosting setup shortcut or `ops/native/host-setup.cmd`. Windows PowerShell 5.1 and Windows Forms are used; no development tools or configuration-file editing are required.
2. Select the complete runtime folder and a new data folder whose parent already exists. Setup refuses existing data, manager files, or COLACK services. Review the suggested chat, database and manager ports. Choose local, trusted LAN or public HTTPS access and enter the browser origin for LAN or public mode.
3. Choose **Install Windows services**. Setup prepares private manager configuration, machine recovery material and a local database, then requests the standard administrator approval for the fixed `COLACKManager`, `COLACKChat` and `COLACKDatabase` services.
4. On the owner setup page, manually copy the single-use claim from the private file identified by setup. The wizard masks the claim and does not copy it to the clipboard. Create the first installation owner; SMTP is optional.
5. Keep the runtime, data and private manager folders in their installed locations. Record their locations and protect the manager recovery file. Setup does not request AI provider credentials.

Local HTTP on `127.0.0.1` is the default. For trusted LAN access, select this host's numeric private IPv4 address and matching chat port, for example `http://192.168.1.42:3000`. Windows registration adds only the fixed chat-service TCP rule for that local address/port and remote LocalSubnet. Manager and database stay loopback-only. A preexisting rule with the reserved name stops registration for local inspection. For public HTTPS, first configure your domain, trusted certificate and reverse proxy to `http://127.0.0.1:<chat-port>`, then enter the pure HTTPS origin. Setup checks trusted TLS reachability before writing state and checks application health after startup. It does not provision DNS, certificates, proxy or internet firewall access.
