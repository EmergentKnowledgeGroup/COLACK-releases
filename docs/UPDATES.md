## Verify and apply

Unlock the independent local manager with its private machine recovery credential. Under **Stage an update**, select the complete extracted signed runtime and choose **Verify and stage update**. Verification/staging leaves running services and current data intact. An incomplete staging folder is not an accepted update. The Windows preview update download is `COLACK-windows-x64-runtime-preview-U20-20261025-r1.zip`; extract all contents into a new folder before selecting it. The hosting installer remains the fresh-install download. Verify the matching archive checksum in the release integrity information, then let the installed verifier check its signed contents.

The installed runtime's `update-publisher-key.bin` is the trust anchor. Its SHA-256 is **96c0598f1f5296f675bdda65649f6a31051149fbd228a90b93843a8f8e030c92**. The candidate cannot choose a replacement verifier. The manager verifies Ed25519 over the exact `update-manifest.json` bytes using `update-manifest.sig`, then checks complete file/directory inventory, lengths, hashes, platform and protocol. Do not edit signed files, disable failed checks, or import a key from an untrusted candidate. Initial installer provenance still matters; unsigned Authenticode is separate from these integrity checks.

For an owned local-runtime installation, choose a new pre-update backup folder outside data/staging and select **Back up and apply update**. New dispatch pauses while active turns finish with their ordinary approvals. Queued requests remain durable. **Cancel drain** releases this pause before application and does not cancel active jobs. The manager creates a complete snapshot and separate candidate data, verifies compiled migration compatibility and trial health, then changes runtime. Expect planned downtime. Reopen the manager with the same private credential and check final service/application health before resuming work.

```sh
  /path/to/manager.json /path/to/signed-candidate /path/to/new-backup-parent
```

The native updater pauses dispatch, waits for active work, snapshots complete state, trials migrations/health in separate private state, then rebinds the fixed systemd services. Preserve the operation records and determine the actual phase before choosing one of these recovery actions.

## Recover a failed or withdrawn release

Failed migration or trial application uses the retained compatible runtime and complete DB/files/configuration/key/recovery snapshot in separate state. Preserve the original state, failed candidate, previous runtime, snapshot and operation records until verified recovery. **Recovery required**, uncertain final status, or unhealthy services is not a completed update. Use authorized host recovery; do not repeatedly rerun installers, merge folders, manually delete migrations or restore an arbitrary older database.

If dispatch may already have resumed, automatic restoration of an older snapshot can discard new work. Preserve the current state and determine the actual operation/health status before any rollback. A runtime-only downgrade is not complete recovery when database compatibility changed. The retained compatible runtime and matching complete snapshot are the recovery pair.

If a release is withdrawn, stop new downloads/update applications of that version and follow its published replacement/recovery advisory. The publisher must visibly mark it withdrawn, stop offering it for new updates, and publish instructions tied to the affected immutable artifact hashes. Published bytes must not be silently replaced. Withdrawal does not authorize deleting user state. Keep your current data and private backups; do not treat an asset disappearing as recovery. Public withdrawal/update-channel delivery has not yet been exercised for this preview candidate.

Signed updates preserve the installation's chosen local/LAN/public mode, listener, browser origins, cookie setting and saved network metadata. Fresh-host restore deliberately starts with local loopback access; inspect the restored owner state and configure the new host's network access before exposing chat.
